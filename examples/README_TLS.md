# TLS Networking Examples

This directory contains a minimal self-contained example showing how to
transmit jitter scores securely over HTTPS, with optional **mutual TLS
(mTLS)**.

> **⚠️ FOR TESTING ONLY** – The certificates generated by
> `scripts/make-certs.sh` are self-signed and must **never** be used in
> production.  For production deployments use a trusted CA (e.g.
> [Let's Encrypt / ACME](https://letsencrypt.org/)), an HSM/TPM, or your
> organisation's PKI.

---

## Files

| File | Purpose |
|------|---------|
| `../scripts/make-certs.sh` | Generate a local test CA, server cert, and client cert |
| `server.py` | aiohttp HTTPS server – listens on `https://localhost:8443` |
| `client.py` | `requests` HTTPS client – POSTs a jitter score |

---

## Quick-start

### 1. Generate test certificates

Run from the **repository root**:

```bash
bash scripts/make-certs.sh
```

This creates the following files under `certs/`:

```
certs/
  ca.key          # Test CA private key  (keep secret)
  ca.crt          # Test CA certificate  (trust anchor)
  server.key      # Server private key   (keep secret)
  server.crt      # Server certificate   (CN=localhost)
  client.key      # Client private key   (keep secret)
  client.crt      # Client certificate
  client.pem      # Combined client.crt + client.key (used by requests/curl)
```

### 2. Install Python dependencies

```bash
pip install "aiohttp>=3.8" "requests>=2.28"
```

Or install via the repo's `requirements.txt`:

```bash
pip install -r requirements.txt
```

### 3. Start the HTTPS server

```bash
python examples/server.py
```

Expected output:

```
2025-01-01 00:00:00  INFO      Starting HTTPS server on https://localhost:8443
2025-01-01 00:00:00  INFO      POST https://localhost:8443/jitter  {'score': <float>}
```

### 4. Send a jitter score (in another terminal)

```bash
python examples/client.py 3.14
```

Expected output:

```
POST https://localhost:8443/jitter  payload={'score': 3.14}
Status : 200
Body   : {"status": "ok", "received_score": 3.14}
```

You can also use `curl`:

```bash
curl -X POST https://localhost:8443/jitter \
  --cacert certs/ca.crt \
  --cert certs/client.crt \
  --key  certs/client.key \
  -H "Content-Type: application/json" \
  -d '{"score": 3.14}'
```

## Enabling mutual TLS (mTLS)

By default the server only authenticates itself (one-way TLS).  To require
the client to present a certificate as well (mTLS), open `examples/server.py`
and uncomment the two lines in `_build_ssl_context()`:

```python
# --- mTLS: uncomment the following two lines to require client certificates ---
ctx.verify_mode = ssl.CERT_REQUIRED                       # mTLS
ctx.load_verify_locations(cafile=str(_CA_CERT))           # mTLS
```

The `examples/client.py` already passes `cert=str(_CLIENT_PEM)`, so it works
with both one-way TLS and mTLS without any changes.

## Adapting for production

| Concern | Recommendation |
|---------|---------------|
| Certificate issuance | Use [Let's Encrypt](https://letsencrypt.org/) (ACME) or your PKI |
| Key storage | Store private keys in an HSM/TPM or a secrets manager |
| Weak TLS versions | `server.py` already disables TLS 1.0/1.1; verify at the load-balancer too |
| Certificate renewal | Automate with `certbot renew` or a cloud-native ACME client |
| Client auth in prod | Issue client certs via your internal CA; rotate on a schedule |
| Secrets in code | Never hard-code paths; use environment variables or a vault |
